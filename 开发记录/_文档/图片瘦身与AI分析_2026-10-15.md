版本：**2.3.3**

## 一、昨天那个 413 是怎么来的

截图里的报错：

```
unexpected status 413 Payload Too Large: HTTP 请求体超过 33554432 字节限制
url: http://127.0.0.1:57321/v1/responses
```

`127.0.0.1:57321` 是本机的 **codex-plus-plus**（把 Codex 的接口转给 DeepSeek 的本地代理），
它限制请求体 **32MB**。

而拆解产出的网格图是：

| 项目 | 数值 |
|---|---|
| 单张网格图尺寸 | 3044 × 2912（11×6 格，每格 480px） |
| 单张 PNG 体积 | **7 ~ 9 MB** |
| 两小时直播产出 | **8 张**，合计 **约 58 MB** |
| 转成 base64 进请求体 | 再 ×1.33 |

看两三张图，请求体就过 32MB → 413。**不是拆解坏了，是图太大。**

## 二、改了什么（底层逻辑）

### 1. 网格图改成小体积 JPEG

改的是引擎 `scripts/frames.py`（产出网格图的地方）：

- 新增 `--grid-format jpg|png`（默认 png 保持不变，向后兼容）
- 新增 `--grid-quality`（JPEG 质量，默认 5）
- 新增 `--max-grid-edge`（限制长边像素）
- 编排脚本 `直播拆解工具.py` 现在固定传：**jpg + 质量 5 + 长边 2400**

实测（同一张真实网格图 3044×2912）：

| 参数 | 单张体积 |
|---|---|
| 原来：PNG 原尺寸 | 9.18 MB |
| 现在：JPEG 长边 2400 / q4 | 1.00 MB |
| 现在：JPEG 长边 2400 / q5 | **0.77 MB** |
| 更狠：长边 1800 / q6 | 0.50 MB |

→ 单张降 **约 12 倍**，两小时直播 8 张从 58MB 降到 **约 6MB**。

App 侧也同步改了：读素材包时 `grid_*.jpg` 和旧的 `grid_*.png` 都认，老素材包不会读不出来。

### 2. 两小时直播到底会产出多少图和多少字

- **图**：引擎按预算封顶（默认 512 帧 / 每张 64 格）→ **最多 8 张**，不随时长增长。
  实测：1 小时（青苔猫）8 张；2 小时（玥盈）也是 8 张。所以图片这块永远在 32MB 以内。
- **字**：随时长线性增长。1 小时素材包实测 **38,818 字**（≈ 2.6 万 token）。
  两小时约 6-7 万字 → 超过单次预算时**自动分片**（默认每片 ≤ 24000 token），一片一片发给 AI 再拼起来，
  所以再长也不会超上下文。

## 三、新增：运营自己就能出 AI 报告

以前是「运营把素材包发给你 → 你贴给 Codex」。现在 App 里直接用：

1. 「设置」页最下面新增 **AI 分析** 区块：接口地址、API 密钥、模型名、单次最多输出
2. 填完点「测试连接」，通了就行
3. 「拆解」页 → 素材包那一栏点 **AI 分析** → 跑完在素材包目录生成 **`AI分析报告.md`**
4. 点「打开分析报告」直接看

接口是 **OpenAI 兼容格式**，所以：

| 服务 | 接口地址 | 模型名示例 |
|---|---|---|
| DeepSeek（和你 Codex 同源） | `https://api.deepseek.com/v1` | `deepseek-chat` |
| 智谱 | `https://open.bigmodel.cn/api/paas/v4` | `glm-4-plus` |
| Kimi | `https://api.moonshot.cn/v1` | `moonshot-v1-32k` |
| 本地 LM Studio / Ollama | `http://127.0.0.1:1234/v1` | 按本地模型名 |

**注意**：DeepSeek 是纯文本模型，看不了图。所以 AI 分析走的是**文字部分**（技术索引 + 逐句话术稿），
图片仍然保留在素材包里给人看。这也是最省成本、最不容易爆上下文的路子。

### 已经做的验证

| 验证项 | 结果 |
|---|---|
| 引擎新参数跑真实录像 | 网格图正常产出，体积 0.659MB → 0.141MB ✓ |
| App 端到端（本地假接口） | 「测试连接」通过；对真实素材包发请求 **38,818 字一次通过**；报告落盘 `AI分析报告.md` ✓ |
| 推理型模型兼容 | 模型把正文放在 `reasoning_content`（`content` 为空）时也能正确取到 ✓ |
| 上游 503 重试 | 自动重试 3 次（0s / 6s / 20s）✓ |

> 说明：刚才用你的本地接口（57321）实测时，上游 DeepSeek 回的是
> `503 Service is too busy`，这是它自己的服务波动，不是我们的问题。
> 运营机器建议直接用 DeepSeek 官方地址 + 你给的密钥。

## 四、DeepSeek 看不了图，那画面怎么分析？

先说清楚：素材包里本来就有两层信息，**文字那层已经占了八成结论**。

| 分析维度 | 靠什么得出 | 需要看图吗 |
|---|---|---|
| 话术库 / 开场 / 留人 / 转化 | 逐句话术稿（带时间戳、原句） | 不需要 |
| 节奏卡点 / 空转段 / 歌与互动配比 | 技术索引里的镜头切换、响度突变、静音 + 自动分段 | 不需要 |
| 镜头切换频率 / 画面变化密度 | 索引里的 shots（每次切镜头的时间点） | 不需要 |
| 机位 / 服装 / 场景 / 表情动作 | 只能看图 | 需要视觉模型 |

所以光靠文字也能出**八成报告**，这也是 DeepSeek 够用的原因。

真想要「看图」两条路：换一个视觉模型当分析接口（千问-VL / 智谱 GLM-4V / Kimi-VL / GPT-4o 等），
把网格图一起发过去（图现在 0.5-0.8MB 一张，发几张不至于爆）；或者自己看，网格图就在 `work\\grid_*.jpg`，每格左上角有时间码。

## 五、运营不用各自买账号：用你这台的 AI（一人一密钥）

新增「**分享给运营**」（设置页）：你这台当服务器，运营填你的地址 + 他自己那把密钥。

- 密钥**一人一个**（`zy-` 开头），能随时单独删掉某个人
- **用量分开统计**：每人调用多少次、传上去多少 token、生成多少 token、最后什么时候用的，设置页列表里直接看
- 上游密钥只在你机器上，不会发给运营

限制：同一局域网、你这台得开着、Windows 防火墙要放行（详见《管理员操作手册》第七章）。

实测（本地假接口跑完整链路）：两把独立密钥各自调用正常（HTTP 200）✓；错误密钥被拒（HTTP 401）✓；用量按人分开计数 ✓。

> token 用量要上游接口返回 usage 才会计；返回不了就只统计调用次数和传入字数。

## 六、运营怎么配

管理员把接口地址、密钥、模型名发给运营，运营在「设置」页填一次即可（存在本机 `%APPDATA%\douyin-live-info\ai.json`）。
之后每次拆完点一下「AI 分析」，报告就出来了，不用再往管理员那里转。
