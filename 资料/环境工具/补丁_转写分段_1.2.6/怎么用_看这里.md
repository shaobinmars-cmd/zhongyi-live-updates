# 补丁：转写长音频不再爆内存（引擎 1.2.6）

**这个补丁解决什么**

运营电脑上报过两种错，都是内存问题，这个补丁一次解决：

1. `[whisper] cpu 加载失败（mkl_malloc: failed to allocate memory）` —— 加载模型时内存不够
   → 现在会**自动降级重试**：联网试 → 只用本地缓存 → **把 CPU 线程降到 1 单线程加载**（省内存）→ 再联网单线程
2. `Unable to allocate 5.36 GiB for an array with shape (1, 1790581, 201)` —— 模型加载成功了，
   但**5 小时的音频一次性算频谱**要 5GB+ 内存（这是 faster-whisper 的默认行为）
   → 现在**自动分段转写**：自己用 ffmpeg 边解码边切，每段 10 分钟，内存只占一段的量（约 300MB）；
   时间戳会加上段偏移，**报告里的时间仍然是整场的**（不会每 10 分钟从头开始）

**怎么用（运营电脑，不用重装软件）**

1. 先**退出正在运行的软件**（任务栏右下角也确认一下没有残留）
2. 打开这个目录（把 `<用户名>` 换成实际用户名）：
   `C:\Users\<用户名>\AppData\Local\Programs\douyin-live-info\resources\engine\scripts\`
   - 快捷方式：按 `Win + R`，粘贴 `%LOCALAPPDATA%\Programs\douyin-live-info\resources\engine\scripts` 回车
   - 如果当初装到了别的盘，就找 `资源\engine\scripts` 这个相对位置
3. 把里面的 `transcript.py` **改名备份**成 `transcript.py.bak`（出问题还能换回来）
4. 把这个文件夹里的 `transcript.py` 复制进去（覆盖）
5. 重新打开软件 → 拆解页 → 再跑一次那场

**验证方法**：跑起来后，日志里应该出现这句

```
[whisper] 音频 298 分钟：按 10 分钟分段转写（省内存，时间戳仍是整场的）…
[whisper] 转写进度 39% 39:59.5 / 298:30.0 已用 …
```

（本机用 26 分钟测试音频验证过：分 3 段、时间戳从 00:54 一路对到 25:30，跨段没有错位。）

**两点建议**

- 5 小时的长场次用 `medium` 在 CPU 上要跑几个小时，**建议这类长场次用 tiny / base**（拆解页的「转写模型」下拉），同样能出报告、快很多。
- 这份补丁只是先让运营顶过今天；下一次出新安装包时会把同样的修复打进 `resources\engine` 里，装上就自动带上，不用再手工替换。
