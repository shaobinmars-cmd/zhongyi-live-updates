> 目标：把「多直播间监控」和「直播拆解」合成**一个** App，发给公司所有运营，每人能盯多个直播间、能拆解自己带的主播，并在主播下播后一键出复盘。

## 二、目标架构

运营电脑只做「不需要额度、纯本地算力」的事；**出报告这一步统一收在你的服务端**，
这样才能做到口径一致、成本可控、能审计。

```
┌─ 运营电脑：直播运营中控台（Electron 单文件 App） ──────────────┐
│                                                                │
│  监控台   多直播间弹幕/礼物/进房/关注 + 实时统计                │
│  录制     ffmpeg 分段录制（已有）                               │
│  拆解     选录制目录 → 触发本地 Python 引擎 → 进度/日志 → 素材包 │
│           └─ Python sidecar：python-embed + scripts + ffmpeg    │
│  复盘     把素材包发给「拆解服务」→ 拿回报告 → 本地留存 + 推飞书 │
│                                                                │
└───────────────────────────┬────────────────────────────────────┘
                            │  HTTPS / 内网
┌───────────────────────────▼────────────────────────────────────┐
│  拆解服务（你这边跑一份，运营连它）                              │
│   · 持有模型凭证，运营电脑拿不到 key                            │
│   · 用你的 Codex 按固定模板出复盘报告                           │
│   · 记录：谁 / 哪个主播 / 哪一场 / 什么时候 / 产出              │
│   · 可选：报告落飞书多维表格                                    │
└────────────────────────────────────────────────────────────────┘
```

**为什么这样切**：运营电脑出「素材包」是 0 token、纯本地的；
「把素材包变成报告」是唯一花钱的环节，收在服务端，你才能统一 prompt、
统一口径、看清谁在用、花了多少。

## 三、分阶段实施

### 阶段 1｜合并外壳 + 本地拆解桥（不依赖服务端）

- 以 `douyin-live-info` 为基座（Electron + Vue）
- 新增「拆解」页；新增 `electron/services/teardown.ts`：
  - `spawn` Python CLI，stdout 按行流式推给渲染进程（进度/日志）
  - 跑完读 `work\拆解素材包.md`，展示 + 一键复制
- 把 `python-embed\`、`scripts\`、`bin\ffmpeg` 作为 `extraResources` 打进包里
- 录制完 → 一键拆解

**交付**：一个 exe，既能盯多直播间，又能出素材包（全程本地、0 token）

### 阶段 2｜复盘服务 + 链接你的 CODEX

- 服务端（Node 或 Python 都行）暴露 `POST /复盘`
- 服务端调用你的 Codex 出报告，**prompt 固定在服务端**，运营改不了
- App「复盘」按钮：传素材包 → 拿报告 → 本地留存 + 展示
- 加：运营身份、主播归属、任务记录表

**交付**：运营点一下，几分钟后拿到一份标准格式的复盘报告

### 阶段 3｜全公司分发 + 管理

- 授权：复用 `v1.3.0-授权版` 的 Ed25519 机器码授权，或改成登录制
- 升级：复用现成的「检查更新 → 自动替换 → 保留数据」机制
- 报告回流飞书（接 `guild-ops`），你在一张表里看**全部运营 × 全部主播**的复盘

### 阶段 4｜复播闭环（最终形态）

- 每个主播一条时间线：每场直播 → 素材包 → 复盘报告 → 下周执行清单
- 自动对比上一场：留存、话术、节奏的变化
- 输出「本周改进项」，下播后直接发给主播

## 四、要提前认下的代价

| 风险 | 说明 | 应对 |
|---|---|---|
| 包体积 | Electron(~200MB) + python-embed + ffmpeg ≈ 400–500MB | 可接受，或首次启动下载引擎 |
| 模型分发 | whisper `small` 约 460MB，`medium` 1.5GB | 随包带 small；medium 按需下 |
| 本机算力 | 一个电脑同时录 N 个直播间 + 转写会卡 | 转写限并发 1；多路录制用流拷贝不转码 |
| 抖音风控 | 多房间并发弹幕/取流有封控风险 | 限速、错峰、备用取流地址 |
| 服务端常开 | 你的 Codex 通道必须一直可达 | 一台常开机器/云主机 + 固定地址 |
| 隐私合规 | 录像是主播的、报告是公司的 | 明确留存期限与访问范围 |

顺手修的两个真问题：

- **后台窗口页面切不动**：Chromium 对被遮住的窗口做渲染节流，切换动画不结束，界面卡在上一页。已加 `backgroundThrottling: false`（7×24 常驻应用本就该关）。
- **`npm run electron:dev` 没连 Vite**：脚本缺 `NODE_ENV=development`，实际读 `dist/`，改代码不生效。已用 `cross-env` 修好。

## 七、需要拍板的三件事

1. **拆解服务放哪** — 你现在这台工位机器常开，还是要一台公司服务器/云主机？
   运营和你是否同一局域网？（决定走内网 IP 还是需要公网/域名）
2. **「链接我的 CODEX」的准确含义** — 是让服务端用你这台机器上的 Codex（Codex++ 那条通道），
   还是你另外给一个 API key 走官方接口？你现在的额度来源就是那个本地网关背后的服务吗？
3. **规模** — 几个运营、一共盯多少个主播/直播间？是否要 7×24 无人值守录制？

确认这三条，阶段 1 可以直接开工。
